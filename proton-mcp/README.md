# proton-mcp

MCP server for the **Proton privacy suite** — Mail, Pass, Drive, and VPN. 31 tools for Claude Desktop and other MCP-compatible AI agents.

Originally created by [jorgenclaw](https://github.com/jorgenclaw/proton-mcp). This is an independent fork — bugs, fixes, and ongoing maintenance live here, not upstream.

## Prerequisites

The `.mcpb` bundle ships the MCP server and all its Node dependencies, but it cannot install the surrounding desktop tools the server talks to. Before first use, make sure each of these is installed and configured on the same machine:

| Requirement | What it's for | Install |
| --- | --- | --- |
| **Node.js ≥ 22** | Runs the MCP server | [nodejs.org](https://nodejs.org) · Windows: `winget install OpenJS.NodeJS.LTS` · macOS: `brew install node` · Linux: distro package or [NodeSource](https://github.com/nodesource/distributions) |
| **Proton Mail Bridge** (running) | All `mail__*` tools (IMAP / SMTP on localhost:1143 / 1025) | [proton.me/mail/bridge](https://proton.me/mail/bridge) — install, sign in, leave Bridge running. Bridge generates a per-app password (NOT your Proton account password) — that's what goes in the Bridge Password field at install time. |
| **pass-cli** (logged in) | All `pass__*` tools | [proton.me/pass/download](https://proton.me/pass/download) — install, then run `pass-cli login` and authenticate. |
| **rclone** with a `protondrive` remote | All `drive__*` tools | [rclone.org/install](https://rclone.org/install) · Windows: `winget install Rclone.Rclone` · macOS: `brew install rclone` · Linux: distro package. Then run `rclone config` and create a new remote named exactly **`protondrive`** using the **Proton Drive** backend. |

### Quick setup check

A bundled `setup.py` / `setup.bat` will check each prerequisite, install the ones that can be installed automatically (Node, rclone via the OS package manager), and surface clear next-steps for the ones that need manual setup (Bridge sign-in, pass-cli login, rclone protondrive remote).

- **Windows**: double-click `setup.bat`, or run it from a terminal
- **macOS / Linux**: `python3 setup.py`

Re-run it any time you suspect something's off — it's idempotent.

## Installation

The easiest path is the `.mcpb` bundle — double-click it and Claude Desktop walks you through configuration.

### Manual installation (developers)

If you want to run from source instead of the `.mcpb`:

```bash
git clone <this-repo>
cd proton-mcp
npm install
cp .env.example .env
# Edit .env with your Proton Bridge credentials
```

## Configuration

When you install the `.mcpb`, Claude Desktop will prompt you for these values. If you're running from source, set them in `.env`:

```env
PROTON_BRIDGE_HOST=127.0.0.1
PROTON_BRIDGE_IMAP_PORT=1143
PROTON_BRIDGE_SMTP_PORT=1025
PROTON_BRIDGE_USER=your@proton.me
PROTON_BRIDGE_PASS=your-bridge-password
PROTON_BRIDGE_FROM=your@proton.me
PROTON_SIGNATURE=                # optional HTML signature
```

The Bridge password lives in **Proton Bridge → Settings → your account → IMAP/SMTP password** — it's generated by Bridge, not your Proton account password.

## Usage

### With Claude Desktop

Install the `.mcpb` — it self-configures via the prompts. No manual config file edit needed.

### Standalone (from source, Node)

```bash
node --env-file=.env index.js
```

The server communicates via MCP stdio protocol.

### Standalone (Python, for OpenCode and other Python MCP hosts)

A pure-Python implementation of the same 31 tools lives next to `index.js` as `proton_mcp.py`. It uses FastMCP (`mcp>=1.0`) and Python stdlib for IMAP / SMTP, with the same `pass-cli` / `rclone` wrappers as the Node version. Tool names match the Node MCP exactly (`mail__get_unread`, `pass__list_items`, etc.).

```bash
pip install -r requirements.txt
python3 proton_mcp.py
```

The script is **fully self-configuring** — hosts like OpenCode that just attach to a running MCP server (without injecting env vars) don't need any extra wiring. `proton_mcp.py` discovers Bridge credentials by walking these sources, in priority order:

1. Process environment (`PROTON_BRIDGE_USERNAME`, `PROTON_BRIDGE_PASSWORD`, etc.)
2. `~/.proton-mcp/bridge.json` — same path and schema the Node MCP reads, so a single file serves both implementations
3. `.env` file next to `proton_mcp.py`
4. `.env` file in the current working directory

Pick whichever fits your setup. Example `~/.proton-mcp/bridge.json`:

```json
{
  "username": "you@proton.me",
  "password": "your-bridge-app-password",
  "imap_host": "127.0.0.1",
  "imap_port": 1143,
  "smtp_port": 1025,
  "from": "you@proton.me"
}
```

Or a `.env` next to the script:

```env
PROTON_BRIDGE_USERNAME=you@proton.me
PROTON_BRIDGE_PASSWORD=your-bridge-app-password
PROTON_BRIDGE_FROM=you@proton.me
```

Either way, just launch `python3 proton_mcp.py` and the running server is ready for any MCP host to pick up.

## Skill for OpenCode / Claude / other local AI runners

A drop-in **skill** lives in `skill/proton-mail/` inside this bundle. Skills are how local AI runners (OpenCode, Claude Code, Copilot CLI, Gemini CLI) learn *when* and *how* to use the Proton tools — without you having to write a giant system prompt yourself.

Install it by copying the skill folder to your runner's skills directory:

**Linux / macOS**

```bash
cp -r skill/proton-mail ~/.agents/skills/
```

**Windows (PowerShell)**

```powershell
Copy-Item -Recurse skill\proton-mail $HOME\.agents\skills\
```

The final layout should be:

```
~/.agents/skills/proton-mail/
├── SKILL.md
├── tools-reference.md
└── workflows.md
```

`SKILL.md` is the always-loaded part — it tells the runner when to invoke the Proton tools (trigger phrases like "check my email", "get my GitHub password", "what's on Drive"). The two helper files are loaded on demand so the prompt stays cheap:

- `tools-reference.md` — full parameter list and return shape for all 31 tools
- `workflows.md` — common multi-step recipes (find-and-reply, secure-credential-update, drive-backup, etc.)

The skill is runner-agnostic. Once the file is in place, OpenCode / Claude / Gemini will discover it automatically the next time they start.

## Security Notes

- The **Proton Bridge password** is NOT your Proton account password — it's a Bridge-specific IMAP/SMTP password generated inside the Bridge app.
- `pass__list_items` and `pass__search_items` never expose passwords or TOTP seeds. Only `pass__get_item` returns the actual password — use it deliberately.
- The `.env` file contains credentials — keep it out of version control. (`.gitignore` already excludes it.)
